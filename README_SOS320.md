## "노트북은 되는데 핸드폰만" 이 결정적 단서였습니다

실전모의고사 화면의 타이머 코드입니다.

```ts
const save = useCallback(async () => { ... }, [activeExam, answers, attempt, examPaused]);
                                                          ↑ 답을 입력할 때마다 바뀜

useEffect(() => {
  const timer    = setInterval(카운트다운, 1000);
  const autosave = setInterval(() => save(), 10000);
  return () => { clearInterval(timer); clearInterval(autosave); };
}, [activeExam, attempt, save, examPaused]);
              ↑ save가 바뀌면 타이머 둘 다 처음부터 다시 시작
```

`save` 함수가 `answers`에 의존하므로, **학생이 글자 하나 입력할 때마다**
`save`가 새로 만들어지고 → useEffect가 다시 돌고 → **타이머 두 개가 통째로 재시작**됩니다.

### 그래서 벌어지는 일

**① 자동저장이 사실상 안 됩니다**

10초 타이머가 매 입력마다 0초로 돌아갑니다.
학생이 답을 이어서 입력하는 동안에는 **10초를 채우지 못해 한 번도 저장되지 않습니다.**

**② 남은 시간이 실제보다 느리게 갑니다**

1초 타이머도 함께 재시작되면서 흘러가던 몇 백 밀리초가 매번 버려집니다.

### 왜 모바일에서만 드러나는가

노트북은 메모리가 넉넉해서 페이지가 그대로 유지됩니다.
자동저장이 안 돌아도 화면에 답이 남아 있으니 아무 일도 없었던 것처럼 보입니다.

**모바일·태블릿은 다릅니다.**
앱을 전환하거나 화면이 잠기면 브라우저가 메모리를 회수하려고 페이지를 정리합니다.
돌아오면 페이지가 다시 열리고 **서버에 저장된 답만 복원**됩니다.
자동저장이 한 번도 안 돌았으므로 **그 사이 입력한 답이 통째로 사라집니다.**

학생 입장에서는 "10초쯤 지나면 리셋된다"로 느껴집니다.

## 고친 내용

### ① 타이머를 입력과 분리

최신 `save` 함수를 ref에 담아두고, 타이머는 ref만 호출합니다.
이제 **입력과 무관하게 10초마다 확실히 저장**됩니다.

### ② 남은 시간을 종료 시각에서 계산

1초씩 빼는 방식은 화면이 꺼지면 타이머가 멈춰 시간이 어긋납니다.
이제 **종료 시각에서 현재 시각을 빼서** 표시합니다.
앱을 전환했다 돌아와도 정확하고, 돌아오는 순간 즉시 다시 맞춥니다.

### ③ 화면을 벗어날 때 저장 — 모바일에서 가장 중요

```ts
visibilitychange (hidden) → 저장
pagehide                  → 저장
```

앱 전환·화면 잠금 직전에 한 번 더 저장합니다.
브라우저가 페이지를 정리해도 **그 시점까지의 답은 서버에 남습니다.**

> 진단·훈련 화면은 처음부터 `Date.now()` 기준이라 같은 문제가 없습니다.
> 실전모의고사 화면만 해당됩니다.
