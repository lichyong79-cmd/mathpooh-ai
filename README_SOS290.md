# SOS290 · 2차훈련 10문항 생성이 계속 죽던 문제

**SQL 1회 실행 + 파일 1개.** 빌드 확인 완료.

```
supabase-sos290-batch-payload.sql   ← Supabase에서 먼저 실행
src\lib\sos-ai-training.ts
```

---

## 증상

- `3제 굳히기 · 3문항` → READY 정상
- `2차훈련 · 10문항` → `5/8 조판 중`에서 멈춤, 하루 뒤 `0/8 생성 작업을 다시 예약했습니다`
- `생성 실패 0`인데 학생은 **"밀린 SOS · 2차 AI 유사훈련 준비 필요"** 상태로 대기

## 원인 — 함수 실행시간 초과

파이프라인은 문항 묶음 하나에 AI를 세 번 부릅니다.

| 단계 | 제한시간 |
|---|---|
| 텍스트 생성 | 70초 |
| 조판 | 80초 |
| 재풀이 검증 | 80초 |
| **합계** | **230초** |

Vercel 함수 한도는 **300초**입니다.

3문항은 각 단계가 가볍게 끝나 완주하지만, **10문항은 문항 수가 3배라 각 단계가 길어져 300초를 넘깁니다.**
조판 도중 함수가 강제 종료되고, SOS271의 안전판이 15분 뒤 회수해 **처음부터 다시 돌리는 일이 반복**됐습니다.

`생성 실패 0`이었던 것도 이 때문입니다. 진짜 실패로 기록되지 않고 계속 재시도만 하고 있었습니다.

## 고친 방법 — 5문항씩 나눠 처리

```ts
const GENERATION_BATCH_SIZE = 5;
```

- **3문항(3제 굳히기)** → 예전과 완전히 동일하게 한 번에 처리. 동작이 바뀌지 않습니다
- **10문항(2차훈련)** → 5문항씩 2묶음으로 나눠 처리

각 묶음이 여유 있게 300초 안에 끝납니다.
그리고 **끝난 묶음은 `batch_payload`에 저장**되므로, 중간에 함수가 죽어도
다음 실행이 남은 묶음만 이어서 만듭니다. 처음부터 다시 돌지 않습니다.

진행 표시도 바뀝니다.

```
이전:  5/8 · 문제집 형태로 수식과 문장을 조판하고 있습니다.
이후:  3/8 · 10문항을 2묶음으로 나눠 생성합니다. (1/2)
```

## 적용 순서

### 1단계 · SQL 먼저 (필수)

Supabase 대시보드 → SQL Editor → `supabase-sos290-batch-payload.sql` 실행.
컬럼이 없으면 배포 후 생성이 오류로 끝납니다.

### 2단계 · 배포

```
cd C:\프로그램_개발\mathpooh-ai
copy src\lib\sos-ai-training.ts sos-ai-training.bak
```

`SOS290` 안의 `src` 폴더를 프로젝트 루트에 덮어쓴 뒤:

```
findstr "SOS290" src\lib\sos-ai-training.ts
git add .
git commit -m "SOS290 AI 생성 배치 분할로 시간 초과 해결"
git push
```

### 3단계 · 멈춰 있던 작업 되살리기

배포 후 **AI 생성 문제은행** 화면에서:

- 멈춰 있는 작업이 다음 cron(10분 이내)에 자동으로 다시 잡힙니다
- 급하면 **「지금 1건 생성」** 을 눌러 즉시 처리할 수 있습니다

배유담·윤동규 학생의 `2차 AI 유사훈련 복구` 버튼도 이제 정상 동작합니다.

## 배포 후 확인

**AI 생성 문제은행**에서 2차훈련 작업의 진행 문구를 보세요.

- `10문항을 2묶음으로 나눠 생성합니다. (1/2)` → `(2/2)` → `READY`
- 한 묶음에 3~4분, 전체 8분 안팎 예상

**`0/8 생성 작업을 다시 예약했습니다`가 더 나오면 안 됩니다.**
계속 나오면 알려주세요. 배치 크기를 3으로 더 줄이면 됩니다
(`src/lib/sos-ai-training.ts`의 `GENERATION_BATCH_SIZE` 상수 하나만 바꾸면 됩니다).

## 참고 · 배치 크기 조정

```ts
const GENERATION_BATCH_SIZE = 5;   // 3으로 낮추면 더 안전, 대신 묶음 수 증가
```

- **5** (현재) — 10문항이 2묶음. 묶음당 약 3~4분
- **3** — 10문항이 4묶음. 더 안전하지만 전체 시간이 늘어남

AI가 느린 시간대에 자주 죽으면 3으로 낮추세요.
