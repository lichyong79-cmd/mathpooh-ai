SOS 164 · 과목 표준화 + 난이도 8단계 실제 적용 + 진행상태 단일화

===============================================================
1. 적용 방법 (윈도우 CMD 기준)
===============================================================

(1) 이 ZIP 안의 src 폴더를 프로젝트 루트에 그대로 덮어쓰기
    - 덮어쓸 파일 18개 (아래 "수정 파일 목록" 참고)
    - 새로 생기는 파일 2개: src\lib\source-workflow.ts, src\lib\difficulty-judge.ts

(2) 환경변수 확인  ★ 이번 수정에서 가장 중요합니다
    .env.local 과 Vercel > Settings > Environment Variables 양쪽에
    아래 값이 있어야 합니다.

        SUPABASE_SERVICE_ROLE_KEY = (Supabase > Settings > API > service_role)

    이 키가 없으면 지금까지처럼 "시험지 과목 수정"이 저장은 된 것처럼 보이지만
    문제은행에는 한 행도 반영되지 않습니다. (RLS가 막는데 에러가 안 뜨는 상태였음)
    SOS164부터는 키가 없으면 화면에 명시적으로 에러 메시지를 띄웁니다.

    선택: OPENAI_DIFFICULTY_MODEL (없으면 OPENAI_MODEL 사용)

(3) 빌드 확인
        npm run build

(4) 배포
        git add .
        git commit -m "SOS164 과목 표준화 + 난이도 8단계 적용 + 진행상태 단일화"
        git push

(5) 추가 SQL 없음 (DB 스키마 변경 없음)

===============================================================
2. 배포 후 반드시 해야 할 정리 작업 (기존 데이터 정리)
===============================================================

■ 과목 정리 (1번 문제)
   관리자 > 문제등록 > [시험지 과목 → 문제은행 전체 동기화] 1회 실행
   → 시험지에 입력된 과목이 문제은행 전 문항에 강제로 다시 씌워집니다.
   → 표준 6과목으로 인식 못 한 시험지는 건드리지 않고 건너뛰며,
      끝난 뒤 "인식 못 한 시험지 N개" 로 알려줍니다. 그 시험지만
      [수정] 눌러 과목을 목록에서 다시 골라 주세요.

■ 난이도 정리 (2번 문제)
   관리자 > 문제은행 > 난이도 탭 > [AI 이상 난이도 검토] 실행
   → 1회 최대 120문항씩 검사합니다. 800문항이면 6~7회 반복 실행하세요.
   → SOS164부터는 "밴드는 3점인데 문항 근거는 4점급"인 문항이
      의심 목록 최상단에 올라옵니다. (예전에는 아예 안 잡혔습니다)
   → 결과를 보고 반영할 문항만 확정하면 됩니다. 자동 변경 아닙니다.

===============================================================
3. 무엇을 고쳤는지
===============================================================

[1] 문제등록 과목이 안 고쳐지고 문제은행 과목이 겹치던 문제

    원인 3가지
    - 등록 시 AI가 만든 과목명이 시험지에 입력한 과목보다 우선했습니다.
      ("미적분", "수학Ⅱ", "확통", "고등수학(상)" 처럼 매번 다르게 씀)
    - src/lib/subject.ts 의 표준화 함수를 만들어만 두고
      실제로는 어디서도 호출하지 않았습니다.
    - 과목별 보유 문항 집계가 원문 문자열을 그대로 세고 있었습니다.
    - 수정/동기화 API가 문항 1개당 요청을 순차로 날려 타임아웃이 났고,
      service role 키가 없으면 조용히 아무것도 안 바꿨습니다.

    수정
    - 과목은 항상 표준 6과목(중등수학 / 공통수학1 / 공통수학2 /
      대수 / 미적분 I / 확률과 통계)으로만 저장합니다.
    - 저장 기준은 언제나 "문제등록에 입력한 시험지 과목"입니다.
      AI가 뭐라고 쓰든 시험지 과목이 이깁니다.
    - problem_dna.basic.subject 도 같은 값으로 맞춰 둘이 어긋나지 않습니다.
    - 문제은행/난이도 탭의 과목 필터·집계도 표준 과목으로만 묶습니다.
    - 수정/동기화 API는 8개씩 병렬 처리 + maxDuration 300초로 올렸습니다.
    - service role 키가 없으면 명확한 에러 메시지를 냅니다.

[2] 8단계 난이도 기준이 신규 문항에 적용 안 되던 문제

    원인
    - src/lib/problem-dna.ts 의 난이도 계산이 csat_difficulty_band
      하나만 보고 등급을 정했습니다. 밴드는 스키마상 필수값이라
      AI가 애매하면 three_point 로 도피했고 → 그대로 "3점" 확정.
      그 아래 있던 가중치 계산(개념·조건해석·발상·계산·함정·시간부담)은
      한 줄도 실행되지 않는 죽은 코드였습니다.
    - 원장님이 1300문항을 직접 재검토한 결과(admin_fixed)는
      난이도 탭 재판정 라우트에서만 참고했고,
      신규 등록 경로는 그 기준표를 아예 보지 않았습니다.

    수정
    - 밴드와 "문항 근거 점수"를 함께 계산하고, 둘이 2단계 이상
      어긋나면 중간값으로 보정합니다. band_conflict 표시도 남깁니다.
      (실측: 밴드=3점 + 근거=적4  → 쉬4 로 보정
             밴드=3점 + 근거=준킬러 → 적4 로 보정
             정상 3점 문항은 그대로 3점 유지)
    - 난이도 판정 엔진을 src/lib/difficulty-judge.ts 한 곳으로 합쳤습니다.
      신규 등록(AI 분석)과 난이도 탭 재판정이 이제 같은 프롬프트,
      같은 8단계 정의, 같은 "관리자 확정 기준 문항"을 씁니다.
    - AI 문항분석이 끝나면 8단계 전용 판정을 한 번 더 돌립니다.
      이때 관리자가 확정해 둔 기준 문항을 같은 과목 우선으로
      최대 16개 붙여 보냅니다. → 1300문항 재검토 기준이 신규 문항에 적용됩니다.
      (기준 문항 조회는 5분 캐시라 800문항 연속 등록해도 조회는 몇 번뿐입니다)
    - 판정 호출이 실패해도 분석 자체는 중단되지 않습니다.

    ※ 문항당 OpenAI 호출이 1회 늘어납니다(작은 호출). 분석 시간이
      문항당 수 초 늘어나는 대신 난이도가 실제로 갈립니다.

[3] AI분석창 상태와 문제입력탭 상태가 다르던 문제

    원인
    - "등록완료"의 정의가 두 개였습니다.
      · 서버: problem_bank_questions 에 해당 문항 행이 있는가
      · AI분석 화면: review_result.bank_status === "REGISTERED" (JSON 플래그)
      재분석하면 이 플래그가 지워져서 두 화면이 어긋났습니다.
    - AI분석 화면의 "검토보류"가 등록완료 문항을 제외하지 않아
      같은 문항이 등록완료와 검토보류에 동시에 세어졌습니다.
    - 같은 로직이 3곳에 복붙돼 있고 라벨 표현도 서로 달랐습니다.
      (분석창 "3단계 분석 · 등록 3 · 대기 5" vs 문제등록탭 "등록대기")

    수정
    - src/lib/source-workflow.ts 를 만들어 상태 판정과 표기를 한 곳으로 모았습니다.
      상태 API 2개, 문제등록 탭, AI분석 화면이 모두 이 파일만 씁니다.
    - AI분석 화면이 서버가 준 등록 문항 목록(registeredQuestionIds)을
      기준으로 판단합니다. 이제 두 화면 숫자가 항상 같습니다.
    - 등록완료 / 등록대기 / 검토보류 / 실패가 서로 겹치지 않습니다.
      (등록완료가 항상 우선)
    - 상태 단어를 통일했습니다:
      미분석 / 분석중 / 등록대기 / 검토보류 / 문제은행 등록완료 / 분석오류
    - 문제등록 탭 상단 요약칩이 5칸 → 6칸(6개 상태)으로 바뀝니다.

5. 확인 방법
===============================================================

1) 문제은행 > 과목별 보유 문항 → 막대가 최대 7개(6과목 + 미분류)만 보이면 정상
2) 문제등록 > 시험지 [수정] > 과목 변경 > 저장
   → "문제은행 N문항 + AI 분석 N문항 동기화" 메시지 확인
   → 문제은행 새로고침 후 과목이 바뀌었는지 확인
3) 새 시험지 1개만 AI 분석 → 난이도가 2(3점)에만 몰리지 않는지 확인
4) 같은 시험지를 문제등록 탭과 AI분석 화면에서 나란히 열어
   상태 단어와 숫자가 같은지 확인
