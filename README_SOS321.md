# SOS321 · 2단 시험지에서 문항번호가 1→3→2→4로 어긋나던 문제

**파일 1개.** SQL 없음. 빌드 확인 완료(49/49).

```
src\lib\crop\question-anchors.ts
```

---

## 증상

`2023 창덕여고 고2 1학기 기말고사`에서

- 박스 1 = 실제 1번 ✓
- 박스 2 = 실제 **3번**
- 박스 3 = 실제 **2번** (위치도 어긋나 내용이 박스 밖에)
- 박스 4 = 실제 4번 (위치 어긋남)

「자르기 기준」은 `PDF 텍스트 좌표 사용 · 문항번호 18개 인식`이었습니다.
**텍스트 레이어는 정상**이었고, 엔진이 읽었는데 결과가 틀렸습니다.

## 원인 — 단(column) 구분 실패

시험지 배치는 이렇습니다.

```
왼쪽 단: 1번(위) → 2번(아래)
오른쪽 단: 3번(위) → 4번(아래)
```

단 구분에 실패하면 페이지 전체를 한 단으로 보고 **위에서 아래로만** 정렬합니다.
그러면 읽는 순서가 `1 → 3 → 2 → 4`가 되고, 번호도 위치도 전부 어긋납니다.

### 왜 실패했나

`detectColumns`는 가운데에서 **완전히 비어 있는 세로 띠**를 찾습니다.

```ts
if (buckets[i] === 0) { ... }   // 한 글자라도 걸치면 실패
```

그런데 이 시험지는 **상단 제목("2023년 창덕여고 고2 1학기 기말고사")과 가로 구분선이
페이지 가운데를 가로지릅니다.** 그 열의 카운트가 0이 아니게 되어
"빈 띠 없음 → 1단"으로 판정됐습니다.

EBS 교재는 그런 전폭 요소가 본문 영역에 없어서 지금까지 문제가 없었습니다.

## 고친 내용

### ① 거의 빈 띠도 단 구분으로 인정

완전히 0인 띠를 못 찾으면, **본문 요소의 6% 이하만 걸치는 띠**를 다시 찾습니다.
소수의 전폭 제목·구분선은 무시하고 실제 여백을 찾아냅니다.

### ② 문항번호 순서로 검증 — 핵심 안전판

임계값 조정만으로는 다른 시험지에서 또 틀릴 수 있습니다.
그래서 **결과가 맞았는지 스스로 확인**하게 했습니다.

시험지 번호는 항상 **쪽 → 단 → 위에서 아래** 순서로 붙습니다.
그 순서로 읽었을 때 번호가 증가하지 않으면 단 구분이 틀린 것입니다.

감지 결과와 반대 가정(1단 ↔ 2단)을 **둘 다 적용해 보고 점수가 높은 쪽**을 씁니다.

```
1단으로 볼 때: 1, 3, 2, 4  →  0.75
2단으로 볼 때: 1, 2, 3, 4  →  1.00   ← 선택
```

동점이면 기존 감지 결과를 유지하므로, **지금까지 잘 되던 EBS 교재는 그대로**입니다.
