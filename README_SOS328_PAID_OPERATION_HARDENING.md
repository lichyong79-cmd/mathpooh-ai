# SOS328 - 유료 운영 안정화

## 적용 내용
1. 같은 5회 묶음/학부모전화/학생명으로 REQUESTED·PAID·ENROLLED 신청이 이미 있으면 재신청으로 상태를 덮어쓰지 않음.
2. 공개 신청 시 학생 전화번호 필수. 신규 학생 계정 생성 실패를 신청 단계에서 예방.
3. 관리자 결제확인·등록 시 회차 5개 연결, 시험 조회/배정, 등록 저장, 최종 신청 상태 저장의 오류를 각각 확인. 중간 오류를 조용히 무시하지 않음.
4. 신청 결제방법을 카드결제(CARD) / 계좌이체(현금영수증)(BANK_TRANSFER)로 저장·표시.
5. 학부모 로그인 화면에 초기 비밀번호 = 전화번호 뒤 4자리 안내 추가.
6. SOS327의 지난 1회차 묶음 신규 신청 차단 유지.

## DB 1회 적용
기존 DB에는 `supabase-sos328-paid-operation-hardening.sql`을 Supabase SQL Editor에서 1회 실행해야 합니다.

## 카드결제 주의
이번 버전은 카드결제를 '신청 결제방법'으로 선택/저장/관리자 확인하는 운영 흐름까지 연결합니다.
실제 카드 승인/취소를 웹에서 자동 처리하는 PG 결제 연동은 결제대행사(PG) 계약/키가 필요하므로 포함하지 않았습니다.
