## SOS321 결과 — 번호 순서는 잡혔습니다

5·6·7·8, 9·10·11·12 모두 단 순서대로 정확히 나왔습니다.
`1 → 3 → 2 → 4` 로 뒤집히던 문제는 해결됐습니다.

## 남은 두 가지 — 원인이 같았습니다

### 증상

- **8번 박스가 문제 중간(조건 상자)에서 시작**하고,
  7번 박스가 8번 첫 두 줄까지 삼킴
- **「문제 인식 통과 →」 버튼이 비활성**

### 원인 ① 단 경계에 걸린 문항번호가 사라짐

단을 나눌 때 **글자의 중심**으로만 판정했습니다.

```ts
const center = (item.left + item.right) / 2;
return center >= leftPx && center < rightPx;
```

이 시험지는 **문항번호가 본문보다 왼쪽으로 튀어나온 양식**입니다.
그래서 오른쪽 단 맨 왼쪽에 붙은 `8.` 의 중심이 경계선 왼쪽에 놓이면
**왼쪽 단으로 넘어가** 버립니다.

넘어간 `8.` 은 같은 높이의 왼쪽 단 본문과 한 줄로 합쳐지고,
그러면 그 줄은 더 이상 `8.` 로 시작하지 않아 **문항번호로 인식되지 않습니다.**

번호를 못 찾으니
- 7번의 아래 경계가 거기서 안 끊겨 → 8번 첫 줄까지 삼킴
- 8번 박스는 엉뚱한 곳에서 시작

**고친 방법** — 경계에 페이지 폭 2%의 여유를 두고,
걸친 글자는 **겹치는 폭이 큰 단**으로 보냅니다.

### 원인 ② 한 문항 때문에 전체가 잠김

```ts
disabled={... || missingRecognitionAnchors.length > 0}
```

위치를 못 찾은 문항이 **하나만 있어도** 다음 단계로 못 갔습니다.
그런데 다음 단계에 **「수동 자르기 화면」** 이 있어서 거기서 직접 맞출 수 있습니다.
정작 고칠 수 있는 화면으로 가는 길이 막혀 있던 셈입니다.

**고친 방법** — 경고만 하고 진행은 허용합니다.

```
위치를 못 찾은 문항이 2개 있습니다 (8, 14번).
그대로 진행하면 그 문항은 자르기 결과가 부정확할 수 있습니다.
다음 단계의 '수동 자르기 화면'에서 직접 맞출 수 있습니다.
진행할까요?
```

버튼 문구도 `위치 미확정 2문항 · 계속 →` 으로 바뀌어,
막힌 게 아니라 진행 가능하다는 걸 알 수 있습니다.

## 아직 남은 것

**박스가 위로 넉넉하게 잡히는 현상** (6·10·12번 등)

앞 문항이 짧아 빈 공간이 크게 남으면, 그 여백이 통째로 뒤 문항 박스에 붙습니다.
`앞 문항의 아래끝 = 뒤 문항의 위끝` 구조라 그렇습니다.

**실제 잘린 이미지는 온전할 가능성이 큽니다.**
「전체 문항 자르기」를 실행하고 문제은행에서 6번이나 10번을 열어
위가 잘렸는지 확인해 주세요.

- 온전하면 → 표시상의 여유일 뿐이니 그대로 두어도 됩니다
- 잘렸으면 → 위쪽 경계를 문항번호 기준으로 다시 잡겠습니다
