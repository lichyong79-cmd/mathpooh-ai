# SOS237 — 중복 미응시 세션 제거 + 학생답 관리

## 1. 진행관리의 이상한 `미응시 0/10` 원인/수정
- 원인: 진단 완료 후 1차훈련 자동생성 요청이 거의 동시에 중복 실행될 경우, 두 요청이 모두 기존 1차훈련이 없다고 판단한 뒤 AI 생성으로 들어가는 레이스 조건.
- 1차훈련 생성에 compare-and-set 방식 생성 잠금을 추가하여 동일 진단에서 1차훈련 AI 생성은 한 요청만 수행.
- 2차 AI 유사훈련/3제 굳히기도 생성 전/insert 직전 기존 세션을 재확인.
- 관리자 SOS 진행관리 조회 시 같은 학생 + 같은 부모 세션 + 같은 단계/회차/cycle의 복제 세션 중 실제 응시 흔적이 전혀 없는 ASSIGNED 세션만 자동 삭제.
- 답안/문항공개/진행 흔적이 하나라도 있는 세션은 자동 삭제하지 않음.

## 2. 학생답 관리
- 관리자 > SOS 진행관리 > 단계 결과 > 각 문항에 `학생답 관리` 추가.
- `최초답` 수정 가능.
- 오답 문항은 `교정답`도 수정 가능.
- 현재 관리자 정답 기준 즉시 재채점.
- 세션 correct_count 즉시 갱신.
- 활동로그에 관리자 수정 전/후 답과 정오 여부 기록.
- 안전상 이미 반영된 과거 바로미터와 이미 생성된 이후 학습 분기는 자동 역산하지 않음. 필요한 경우 기존 `이 단계부터 다시` 기능으로 재진행 가능.

## 3. 기존 SOS236 유지
- 모든 진단/1차/2차/3제의 관리자 `정답 관리` 유지.
- 3제 굳히기 바로미터 미반영 유지.
- SOS235 최종 완료 화면/AI 제한변형 검증 유지.
- 신규 Supabase SQL 없음.
