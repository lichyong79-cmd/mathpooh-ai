## 1) 신규문항이 자동으로 검증됩니다

### 이전 흐름

1. AI가 DNA 분석
2. 공식이 DNA 점수로 난이도 **추정**
3. 추정이 쉬4 이상이면 AI 검증, 아니면 추정치 그대로 확정

공식은 낮게 매기는 경향이 있어(2점·3점에 2963개가 몰린 이유),
실제로는 쉬4인 문항이 3점으로 나오면 검증에서 빠지고 그대로 굳었습니다.
**지금 4723건을 만든 것과 똑같은 일이 신규문항에서 계속 반복될 구조였습니다.**

### 이후 흐름

문항 등록 시(`registerAnalyzedQuestions`), AI 검증을 못 받은 문항을
**자동으로 재판정 큐에 넣습니다.**

- 등록 즉시 → 추정치로 바로 사용 가능 (학습에 지장 없음)
- 몇 시간 안에 → cron이 AI 검증
- 결과가 다르면 → 조용히 교체

우선순위는 기존과 같습니다: 미분류 → 3점·어3 → 나머지.
큐 등록이 실패해도 문항 등록 자체는 막지 않습니다.

## 2) 이미 판정한 문항은 다시 안 돕니다

`대기열에 넣기` 버튼과 자동 등록 모두, `ai_regrade_version`이 있는 문항을 제외합니다.

특히 **검토필요로 남은 문항**이 대상입니다.
AI가 등급은 냈지만 정답 대조나 신뢰도에 확인이 필요하다고 본 것들인데,
이건 AI를 다시 돌린다고 풀리지 않습니다 — 관리자가 화면에서 확정해야 합니다.
재실행은 비용만 듭니다.

> 강제로 다시 돌려야 할 때는 API에 `{ "force": true }`를 보내면 됩니다.
> 화면 버튼에는 노출하지 않았습니다.

## 3) 등록 시 인라인 검증을 7로 되돌림

SOS275에서 `VERIFY_FROM_GRADE`를 7 → 4로 내렸습니다.
그때는 인라인 검증이 유일한 검증 경로라고 봤기 때문입니다.

그런데 확인해 보니 **등록 시점의 이 검증은 결과를 실제 난이도에 반영하지 않고**
`verification_*` 메타만 남깁니다. 그래서 큐가 같은 문항을 한 번 더 판정하게 되어
**AI 호출이 두 배로 듭니다.**

이제 검증은 큐가 맡으므로 7로 되돌렸습니다.
준킬러 이상만 등록 화면에서 곧바로 눈에 띄도록 남겨 뒀습니다.
등록도 그만큼 빨라집니다.
