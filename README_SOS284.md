## 1) 주차가 안 맞던 문제

`monthWeekOfMonday`가 **1일이 속한 주의 월요일**을 그 달의 기준점으로 잡았습니다.
그 월요일이 **지난달일 수 있다는 걸** 놓쳤습니다.

2026년 8월 1일은 토요일이라 기준점이 **7월 27일**이 됩니다.
그 결과 이렇게 밀렸습니다.

| 주 시작 | 이전(잘못) | 이후(정상) |
|---|---|---|
| 8/3 (월) | 8월 **2**주차 | 8월 **1**주차 |
| 8/10 | 8월 3주차 | 8월 2주차 |
| 8/17 | 8월 4주차 | 8월 3주차 |
| 8/24 | 8월 5주차 | 8월 4주차 |
| 8/31 | 8월 **6**주차 | 8월 **5**주차 |

**8월 1주차가 아예 없고 6주차까지 나오던** 상태였습니다.

이제 **그 달의 첫 월요일을 1주차**로 셉니다.

```ts
const offset = (8 - first.getDay()) % 7;              // 1일 이후 첫 월요일까지의 일수
const firstMonday = new Date(y, m, 1 + offset);
```

### 저장된 라벨도 자동으로 교정됩니다

`weekFromSnapshot`이 스냅샷에 저장된 라벨을 계산값보다 우선했습니다.
그래서 세션 만들 때 찍힌 잘못된 라벨이 그대로 따라다녔습니다.

이제 **어느 주인지(주 시작일)는 스냅샷을 그대로 믿되, 표시 라벨은 항상 다시 계산**합니다.
DB를 건드리지 않고 과거 세션의 표기도 바로잡힙니다. **마이그레이션 불필요합니다.**

> 다만 "지난주·이번주가 둘 다 8월 4주차"로 보이셨다면, 두 세션이 실제로
> 같은 주에 만들어졌을 가능성도 있습니다. 배포 후에도 같아 보이면
> 아래 쿼리로 주 시작일을 확인해 주세요.
>
> ```sql
> select created_at, phase, round_no,
>        target_snapshot->>'sosWeekStart' as 주시작일,
>        target_snapshot->>'sosWeekLabel' as 저장된라벨
> from public.sos_training_sessions
> order by created_at desc limit 12;
> ```
>
> 주시작일까지 같으면 라벨이 맞는 것이고, 다른데 라벨이 같으면 알려주세요.

## 2) 진행탭 — 학생별로 묶기

`/admin/sos-progress`는 **회차별로만** 묶여 있었습니다.
한 회차 안에 여러 학생의 진단·훈련 단계가 이어져 나와서,
한 학생이 어디까지 갔는지 보려면 눈으로 골라내야 했습니다.

필터 바 오른쪽에 **묶음 토글**을 넣었습니다.

- **학생별** (기본) — 학생 이름으로 밴드를 나누고, 그 안에서 최신 회차 → 생성 순
  밴드에 `학교 · 학년 · 단계 n개 · 완료 n · 진행중 n` 요약이 함께 나옵니다
- **회차별** — 기존 방식 그대로

기존 검색·회차·단계·상태 필터는 그대로 동작합니다.
