# SOS278 · 난이도 재판정 백그라운드 처리

**SQL 1회 실행 + 파일 3개.** SOS277 위에 덮어쓰세요. 빌드 확인 완료.

```
supabase-sos278-difficulty-regrade-queue.sql   ← Supabase에서 먼저 실행
src\app\api\cron\sos-difficulty-regrade\route.ts       (신규)
src\app\api\problem-bank\difficulty-queue\route.ts     (신규)
src\app\problem-bank\difficulty\page.tsx               (교체)
```

---

## 왜 필요한가

48문항에 10분 = **문항당 약 12.5초**.
AI 미검증 4723문항이면 **약 16시간**입니다.
브라우저 탭을 16시간 켜두는 건 불가능하고, 중간에 끊기면 처음부터입니다.

큐에 넣어두고 서버가 10분마다 조금씩 처리하도록 옮깁니다.

| 한 번당 | 소요 | 300초 한도 |
|---|---|---|
| **8문항** | 약 100초 | 여유 충분 ← 채택 |
| 16문항 | 약 200초 | 빠듯 |
| 24문항 | 약 300초 | 초과 위험 |

**시간당 48문항, 하루 약 1150문항.** 4723문항은 **3~4일**이면 끝납니다.
브라우저는 닫아두셔도 됩니다.

## 무엇이 만들어지나

### 1) 큐 테이블 `sos_difficulty_regrade_jobs`

문항별로 대기/처리중/완료/실패 상태와 판정 전후 난이도를 기록합니다.
`question_id`가 unique라 같은 문항이 중복으로 들어가지 않습니다.

### 2) 워커 `/api/cron/sos-difficulty-regrade`

- 우선순위 순으로 8문항을 선점하고 **즉시 202** 응답 → 외부 스케줄러 30초 타임아웃에 안 걸림
- 실제 판정은 `after()`로 이어서 진행 (SOS271과 같은 방식)
- `RUNNING`으로 20분 이상 멈춘 작업은 자동 회수
- 3회까지 재시도, 그 이상은 FAILED로 확정
- 저장 기준은 화면 재판정과 **완전히 동일**합니다.
  미판정·검토필요는 기존 난이도를 유지하고 검증 메타데이터만 남깁니다.

`CRON_SECRET`은 기존과 같은 값을 씁니다. 프록시 예외(`/api/cron/`)도 이미 적용돼 있습니다.

### 3) 처리 순서

```
미분류(414)  →  3점·어3(1905)  →  나머지
```

값이 아예 없는 것부터, 그다음 경계가 가장 흐린 구간, 마지막이 나머지입니다.
**관리자 확정 문항과 AI 확정 문항은 대상에서 빠집니다.**

### 4) 난이도 화면에 진행 카드

KPI 아래에 진행률 막대와 대기/처리중/완료/실패/건너뜀 숫자가 뜹니다.
30초마다 자동 갱신되고(탭이 활성일 때만), 버튼 네 개가 있습니다.

- **AI 미검증 문항 대기열에 넣기** — 큐 채우기
- **실패 N건 재시도** — 실패분만 다시 큐로
- **대기 비우기** — 아직 처리 안 한 대기 건만 삭제(완료 결과는 보존)
- **새로고침**

### 3) cron-job.org에 작업 하나 더 등록

기존 AI 문항 생성 작업은 **그대로 두고**, 새 작업을 추가합니다.
학생 학습과 완전히 분리되어 서로 시간을 뺏지 않습니다.

| 항목 | 값 |
|---|---|
| Title | SOS 난이도 재판정 |
| URL | `https://mathpooh-ai.vercel.app/api/cron/sos-difficulty-regrade` |
| Schedule | Every 10 minutes |
| ADVANCED → Headers Key | `Authorization` |
| Value | `Bearer (기존과 같은 CRON_SECRET 값)` |

`Bearer` 뒤 공백 한 칸. 저장 후 **TEST RUN**.

- `200` + `processed:0` → 정상 (아직 큐가 비어 있음)
- `202` → 정상 (작업 시작)
- `401` → 헤더 오타

### 4) 큐 채우기

난이도 관리 화면 → **AI 미검증 문항 대기열에 넣기**

약 4700건이 들어갑니다. 10분 뒤부터 진행률이 오르기 시작합니다.

## 지켜볼 점

**첫날은 하루 한두 번 진행 카드를 확인해 주세요.**

- **완료가 늘고 실패가 0에 가깝다** → 그대로 두시면 3~4일 뒤 끝납니다
- **실패가 빠르게 쌓인다** → 판정 자체에 문제가 있습니다. 실패 항목의 원인을 봐야 합니다
- **처리중이 계속 8에 멈춰 있다** → 워커가 죽은 것입니다. 20분 뒤 자동 회수되니 조금 기다려 보시고, 그래도 안 움직이면 알려주세요

**중간에 멈추고 싶으면** cron-job.org에서 해당 작업을 Disable 하면 됩니다.
큐는 그대로 남아 있어 나중에 다시 켜면 이어서 진행됩니다.

**AI 비용**은 문항당 2회 호출입니다. 4723문항이면 약 9400회.
부담되시면 큐를 비우고 과목이나 등급을 좁혀 다시 넣는 방법도 있습니다.
