# SOS235 · AI 유사문항 안정화 + 3제 굳히기 + 최종 완료

기준: SOS234 UI polish

## 1. AI 유사문항 안정화
- 1차 훈련 문항의 실제 원문 이미지(question-images)를 AI 생성 입력에 직접 전달합니다.
- 자유 생성이 아니라 원문의 핵심 개념/풀이 흐름/질문 유형을 유지하는 제한변형만 허용합니다.
- 생성 뒤 별도 AI 검수 단계가 원문과 대조하고, 출제자의 answer/solution을 믿지 않은 채 처음부터 독립 재풀이합니다.
- 원문 충실도(sourceFaithful), 유일해, 조건 모순, 정수 정답, 재계산 정답 일치가 모두 통과한 문항만 세션에 저장합니다.
- 최대 3회 재생성/재검증 후에도 실패하면 잘못된 문항을 저장하지 않고 명시적으로 실패합니다.

## 2. 1차 통과자 AI 유사문항 3제 굳히기
- 기존 HOMEWORK 세션 스키마를 유지해 DB 마이그레이션 없이 동작합니다.
- 학생 UI 명칭을 `AI 유사문항 3제 굳히기`로 통일했습니다.
- 시간 제한 없음 안내를 표시합니다.
- 최초 정답/오답, 재도전, 힌트 1·2단계, 3회 실패 후 정답·핵심풀이 확인, 교정완료 기록은 기존 오답 엔진을 그대로 사용합니다.
- 제출 채점은 별도 분기로 처리하여 `recordTrainingResult`를 호출하지 않습니다.
- 따라서 3제 굳히기는 sos_difficulty_events, 학생 바로미터, 문항 바로미터에 반영되지 않습니다.

## 3. 최종 SOS 완료 화면
다음 두 경우 동일한 최종 완료 화면으로 종료됩니다.
- 1차 훈련 통과 → AI 유사문항 3제 굳히기 및 필요한 오답 교정 완료
- 1차 훈련 미달 → 2차 AI 유사훈련 → 오답 전부 교정 완료

최종 화면:
- CSS 컨페티
- `SOS 공략 완료! 금주의 학습이 모두 종료되었습니다.`
- 공략 영역/취약점
- 시작 바로미터 → 최종 바로미터 및 목표
- 이번 SOS 최초 정답 합계
- 이번 SOS 단계 연결 요약
- `전체 결과보기` 버튼 및 단계별 결과 재진입

## 호환성
- 신규 Supabase 테이블/컬럼/SQL 없음
- SOS234 기존 데이터 구조 유지
- 기존 진단, 1차 훈련, 2차 훈련, 오답 엔진/힌트 룰 유지

## 검증
- 변경 TS/TSX 5개 파일은 TypeScript `transpileModule` 구문 검증 통과
- 전체 `next build`는 작업 환경에서 npm registry DNS 접근이 차단되어 의존성 재설치가 불가능해 실행하지 못했습니다. 원본 ZIP에도 node_modules는 포함되지 않습니다.
