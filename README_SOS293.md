## 원인 — 화면에 안 쓰이는 데이터로 작업을 실패시킴

조판 단계는 문항마다 두 가지를 만듭니다.

| 데이터 | 용도 |
|---|---|
| `displayLatex` | **학생 화면에 실제로 표시되는 것** |
| `renderBlocks` (MathML) | 예비 데이터. 화면에서 쓰이지 않음 |

학생이 보는 것은 `displayLatex`뿐입니다.
`renderBlocks`는 `displayLatex`가 없을 때만 쓰이는 대비책인데,
지금은 항상 `displayLatex`가 만들어지므로 사실상 사용되지 않습니다.

그런데 검수는 **그 MathML에 LaTeX 명령이 섞였다는 이유만으로**
멀쩡한 문항 3개를 통째로 버리고 처음부터 다시 만들게 했습니다.

> MathML과 LaTeX는 표기법이 다릅니다.
> AI가 MathML을 쓰다가 `\frac` 같은 LaTeX 명령을 섞는 일이 잦은데,
> 이건 정답이나 문제 내용과는 아무 상관이 없습니다.

## 고친 방법

**① 검수 실패 사유에서 제외**

MathML 오염은 더 이상 작업을 실패시키지 않습니다.
`displayLatex`에 대한 검수(수식 구분자 짝, 환경 짝, 원시 지수표기 등)는 그대로 유지됩니다.

**② 오염된 블록만 걷어냄**

```ts
function cleanRenderBlocks(raw) { ... }
```

LaTeX 명령이 섞인 MathML 블록만 빼고 나머지는 남깁니다.
버리는 게 아니라 정리하는 방식입니다.

**③ 프롬프트에 명시**

> renderBlocks의 mathml 값에는 LaTeX 명령을 절대 넣지 않습니다.
> 확신이 없으면 mathml 블록을 비우고 text 블록만 반환하세요.

애초에 오염이 덜 생기게 하고, "확신 없으면 비워라"는 탈출구를 줍니다.

## 다음에 나올 수 있는 실패

이 파이프라인은 검수 단계가 여러 겹입니다. 아직 남은 것들입니다.

- **`재풀이 검증 실패`** — AI가 자기가 만든 문제를 다시 풀었는데 답이 다른 경우.
  이건 **정당한 실패**입니다. 틀린 문제를 학생에게 주지 않으려는 장치이므로 그대로 두는 게 맞습니다.
  다만 반복되면 텍스트 생성 품질 문제이므로 알려주세요.
- **`정답이 정수가 아님` / `정답 범위 오류`** — 문항 자체를 다시 만들면 해결됩니다.

**`조판 검수 실패`가 또 나오면** 어떤 사유인지 알려주세요.
`displayLatex` 쪽 사유라면 그건 실제로 화면에 영향을 주는 것이라 다르게 접근해야 합니다.
