# SOS326 · 탈퇴한 학부모가 다시 가입해도 자녀 연결이 안 되던 문제

**파일 4개.** SQL 없음. 빌드 확인 완료(56/56).
**SOS325를 포함하지 않으므로 325를 먼저 적용**해 주세요.
(withdraw 라우트와 admin/page.tsx는 SOS325 위에 덮어쓰는 최신본입니다.)

## 지적하신 대로 문제가 있었습니다

세 가지가 겹쳐 있었습니다.

### ① 탈퇴하면 자녀 연결이 무조건 끊겼습니다

SOS325의 탈퇴 처리는 **항상** 학생의 `parent_phone` 을 비웠습니다.
그러면 같은 번호로 다시 가입해도 시스템은 그 학부모의 자녀를 알 수 없습니다.

**고친 방법** — 탈퇴 시 물어봅니다.

```
자녀와의 연결 정보를 남겨둘까요?

[확인] 남겨둡니다 — 같은 번호로 다시 가입하면 자녀가 자동으로 다시 보입니다.
        (잠시 쉬거나 비밀번호를 초기화하는 경우)

[취소] 연결도 끊습니다 — 완전히 그만두는 경우.
```

연결을 남겨두면 **재가입만으로 자녀가 그대로 돌아옵니다.**

### ② 재가입해도 연결된 자녀를 알려주지 않았습니다

이미 같은 번호로 연결된 자녀가 있어도 가입 응답은 아무 말이 없었습니다.
학부모는 자녀가 이미 연결됐는지 모른 채 다시 등록을 시도하게 됩니다.

**고친 방법** — 가입 시 연결된 자녀를 확인해 알려줍니다.

```
가입이 완료되었습니다. 등록된 자녀 2명(배유담, 윤동규)이 자동으로 연결되었습니다.
```

### ③ 「기존 자녀 연결」이 이름을 완전히 일치시켜야 했습니다

```ts
.eq("name", name)   // 한 글자, 공백 하나만 달라도 실패
```

저장된 이름에 공백이 섞였거나 학부모가 조금 다르게 입력하면
`일치하는 기존 학생을 찾지 못했습니다` 가 떴습니다.
**자녀를 알고 있는데도 연결이 막히는** 상황이었습니다.

**고친 방법** — 전화번호로 먼저 찾고, 이름은 공백을 무시해 비교합니다.
전화번호는 학생마다 고유하므로 이것만으로 특정됩니다.

안내 문구도 상황에 맞게 갈랐습니다.

| 상황 | 이전 | 이후 |
|---|---|---|
| 번호가 아예 없음 | 일치하는 기존 학생을 찾지 못했습니다 | 해당 번호로 등록된 학생을 찾지 못했습니다. 번호를 확인하시거나 학원으로 문의해 주세요 |
| 번호는 있는데 이름이 다름 | (같은 문구) | 해당 번호는 다른 학생(배○○)으로 등록되어 있습니다. 학생 이름을 확인해 주세요 |

이름 일부만 보여주므로 다른 학생의 개인정보가 노출되지 않으면서도,
학부모가 번호를 잘못 넣었는지 이름을 잘못 넣었는지 알 수 있습니다.

## 배포 후 확인 — 테스트용 번호로 하세요

1. 테스트 학부모 계정을 만들고 자녀를 하나 연결
2. 관리자 → **「학부모 탈퇴」** → 두 번째 물음에서 **[확인]**(연결 남김) 선택
3. 같은 번호로 `/parent-signup` 에서 다시 가입
4. **가입 직후 자녀가 그대로 보이는지** 확인

연결을 끊는 쪽([취소])도 한 번 해보시고,
그 경우 「자녀 관리」 → 「기존 자녀 연결」로 다시 붙는지 확인해 주세요.

## 정리 · 어떤 경우에 무엇을 쓰나

| 상황 | 사용할 기능 |
|---|---|
| 한 자녀만 연결이 잘못됨 | 학생정보 → **자녀 연결 끊기** (SOS324) |
| 학부모가 잠시 쉼 / 비밀번호 초기화 | **학부모 탈퇴** → 연결 **남김** → 재가입 |
| 학부모가 완전히 그만둠 | **학부모 탈퇴** → 연결 **끊음** |
| 학생이 잠시 쉼 | 학생정보 → 상태를 **휴원** 으로 (SOS325) |
| 학생이 그만둠 | 학생정보 → 상태를 **퇴원** 으로 |

어느 경우에도 **학생의 학습기록은 지워지지 않습니다.**
