## 왜 필요한가

계정 자체는 충돌하지 않습니다. 도메인이 달라 별개 계정으로 만들어집니다.

```
01026481325@student.matspu.local   ← 학생
01026481325@parent.matspu.local    ← 학부모
```

문제는 **실제 운영에서 생깁니다.**

- 같은 사람이 학생이면서 자기 자신의 학부모가 되는 셈입니다
- **초기 비밀번호가 완전히 같아집니다** (`Mp!` + 뒤 4자리)
  한쪽 번호를 아는 사람이 다른 쪽도 열 수 있습니다
- 관리자가 학생정보를 볼 때 잘못 입력한 건지 의도한 건지 구분이 안 됩니다

학부모가 **자녀 번호 칸에 자기 번호를 적는 실수**가 흔한데,
그러면 학부모 계정이 자녀를 찾지 못하고 원인도 알아채기 어렵습니다.

## 어떻게 동작하나

**막지 않고 확인만 받습니다.** 형제자매나 특수한 사정이 있을 수 있어
완전히 차단하면 오히려 곤란해집니다.

### 관리자 · 학생정보 저장 시

```
학생 번호와 학부모 번호가 같습니다.

학부모가 자녀 번호를 잘못 적은 경우일 수 있습니다.
이대로 두면 학생 계정과 학부모 계정의 초기 비밀번호도 같아집니다.

그대로 저장할까요?
```

### 학부모 · 자녀 등록 시

서버가 먼저 확인을 요청하고, 화면에서 다시 물어봅니다.

```
입력하신 번호가 학부모님 번호와 같습니다.
자녀의 휴대폰번호가 맞는지 확인해 주세요.

그대로 진행할까요?
```

확인을 누르면 그대로 진행됩니다.

## 계정 정리 작업 순서

배포가 끝나면 정리하시면 됩니다.

### 1) 학부모 계정 3건 탈퇴

관리자 → 학생정보 관리 → **「학부모 탈퇴」** 를 세 번 반복합니다.

```
01094715672   안채은
01026481325   오예진
01047281972   (이름 없음 · 오타 계정)
```

셋 다 연결된 자녀가 없으므로, 두 번째 물음에서 **[취소]**(연결도 끊음)를 고르시면 됩니다.
어느 쪽을 골라도 결과는 같습니다.

### 2) 확인

```sql
select u.email, u.raw_user_meta_data->>'name' as 이름
from auth.users u
where u.raw_user_meta_data->>'role' = 'parent'
  and not exists (
    select 1 from public.students s
    where s.parent_phone = u.raw_user_meta_data->>'parent_phone'
  );
```

**0건**이 나오면 정리 완료입니다.

### 3) 남는 상태

- 학생 5명 : 최현슬, 배유담, 윤동규, 베트맨, 이수학
- 학부모 4명 : 정상 연결
- 이수학은 학부모 연결 없음 (필요할 때 붙이면 됩니다)
