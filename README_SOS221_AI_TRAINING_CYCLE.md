# SOS221 · AI 취약점 → 훈련 사이클

## 적용 순서
1. Supabase SQL Editor에서 `supabase-v3.4-sos-training-cycle.sql` 실행
2. 코드 배포
3. 기존 완료 진단이 아니라 **새 진단 3문항**으로 한 사이클 테스트 권장

## 이번 버전 핵심
- 진단 3문항 제출 직후 AI가 정오답·풀이시간·문항 DNA·풀이사진을 함께 분석
- 취약점 발견 시 학생에게 취약점 제목/설명을 저장하고 1차 맞춤훈련 10문항 자동 생성
- 1차 훈련은 문제은행에서 AI가 실제 관련성을 보고 선정
- 난도는 전체적으로 조금 쉽게 시작: 기초 안정화 → 핵심 보완 → 포함 적용 → 완성 확인
- 훈련은 한 문항씩 진행하며 **문항별 풀이시간을 정확히 저장**
- 훈련 바로미터 반영은 정오답 + 풀이시간을 함께 사용
- 오답이 있으면 무조건 오답 재풀이 단계 진행
- 오답은 본훈련보다 작은 보정값만 반영(전체 최대 +0.05)
- 구간별 목표 상승폭
  - 1.00~3.99: +0.30
  - 4.00~5.99: +0.20
  - 6.00~6.99: +0.15
  - 7.00~7.49: +0.10
  - 7.50~8.00: +0.05
- 1차 목표 달성 → AI 유사·변형문항 3개 숙제 자동 생성(바로미터 미반영)
- 1차 목표 미달 → 1차 오답/지연 문항 DNA를 바탕으로 AI 유사·변형문항 10개 2차 훈련 자동 생성
- 2차 훈련도 오답 필수, 이후 그 주 훈련 종료. 목표 미달이면 완료/집중관찰 상태로 남김
- 1차 진단에서 뚜렷한 취약점이 없으면 학생의 다른 최저 바로미터 영역으로 2차 진단 3문항 자동 배정
- 2차 진단에서도 취약점이 없으면 그 주 진단 종료

## 관리자 화면
- 진행: 성적/정오답을 제거하고 `배정·시작·진도·완료·소요시간·활동로그`만 표시
- 결과: `진단결과 / 훈련결과` 분리
- 훈련결과에서 AI 취약점, 시작/목표/훈련후/오답후 바로미터, 본훈련 답안/시간, 오답 재풀이 결과, AI 생성 유사문항 확인

## 바로미터 반영 정책
- 기존 진단 엔진은 기존 난이도 미터 반영 유지
- 본훈련은 10문항 한 세트를 잘했을 때 대략 +0.2 안팎이 움직일 수 있도록 작은 K값(0.05) 사용
- 정답이어도 풀이시간이 지나치게 길면 상승 효과 축소
- 오답 재풀이 성공은 소폭 보너스만 부여
- AI 유사문항 3개 숙제는 바로미터에 반영하지 않음

## 새 DB 필드
`weakness_snapshot`, `baseline_meter`, `goal_meter`, `training_meter`, `review_meter`, `cycle_kind`, `generated_problem`, 오답 재풀이 관련 필드가 추가됩니다.
